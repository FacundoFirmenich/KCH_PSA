# Reconciliación remota KCH / Jarvis — 2026-11-05

## Posición sustantiva

La evidencia remota posterior a agosto modifica la fotografía inicial de `KCH_PSA`: Jarvis no quedó únicamente especificado ni reducido a un bot. Existen varias líneas materialmente construidas, instaladas y, en jurisdicciones acotadas, activadas. Sin embargo, esas líneas no forman una secuencia semántica única sólo porque sus versiones sean comparables como números.

La regla de integración es:

```text
identidad de producto + genealogía + artefacto + host + receipt
> comparación superficial de versiones
```

No se importará autoridad, estado operativo ni superioridad desde un checkpoint histórico. Los contratos útiles se reimplementarán en `KCH_PSA` con procedencia, tests y receipts propios.

## Decisiones vinculantes para KCH_PSA

1. **KCH-first, superficies reemplazables.** KCH conserva misión, autoridad, procedencia y receipts. Jarvis, Telegram, Ava/Playpad y los IDE son superficies o productos relacionados, no soberanos semánticos.
2. **Mancomunidad confederada.** Cada motor conserva identidad, ciclo de vida, permisos y evidencia. La reconciliación se hace sobre contratos comunes; conectar no significa fusionar.
3. **Estado durable y explícito.** `STOPPED` es una orden persistente, no un error que deba autocorregirse. Reiniciar requiere autoridad aplicable y deja receipt.
4. **Preferencia capturada por ejecución.** Los modos de trabajo son reversibles, pertenecen a un ámbito explícito y se congelan al comenzar cada turno. No se propagan a otras tareas por arrastre.
5. **Efectos separados de presentación.** Una respuesta rica puede degradar a texto sin perder el contenido completo. URL, autenticación, jurisdicción, lease, revocación y entrega son gates distintos.
6. **Audio por etapas.** Original, normalización, transcripción, corrección, aprobación, ejecución y respuesta hablada son objetos enlazados; ninguno se infiere desde el siguiente.
7. **Ava no se reduce a estética.** El objetivo desktop conserva explorer, search, Git, editor, terminal/problems/output/debug y sidecar, con fronteras nativas adaptadas sin Rust y autoridad verificable por acción.
8. **KwanTau DOS es dirección, no deployment.** Se conserva como entorno operativo en espacio de usuario con procesos, recursos, continuidad y superficies; el repo histórico OpenClaw no demuestra esa realización.
9. **Cloud-first sin ficción de sincronización.** Drive es custodia primaria y GitHub historial de código. Una copia o backup manual no demuestra sincronización continua.
10. **PHL sigue separado.** Memoria, configuración aprendida, feedback, skill staged, promoción y entrenamiento paramétrico no se colapsan. PHL no se ejecuta en esta reconciliación.

## Bloqueo host observado

Durante esta reconciliación, C: cayó a 634.880 bytes libres. `KCH_PSA` ocupa decenas de KB en sus artefactos de build y no explica la saturación. La auditoría read-only de Codex encontró 4.912.498.702 bytes de rollouts nuevos ausentes del baseline y 324.815.394 bytes cambiados desde el baseline; todos quedaron en `RETAIN`. No se borró, movió, comprimió ni archivó nada.

Hasta recuperar espacio sin pérdida:

- las lecturas remotas y la adjudicación pueden continuar;
- no se deben ejecutar builds, instalaciones o campañas locales;
- el checkout local puede quedar detrás del remoto;
- no se tocarán PDFs, fuentes del usuario, sesiones nativas ni material de otros chats.

## Siguiente gate

Implementar sobre el kernel neutral ya existente:

1. máquina de estados durable `STOPPED → START_AUTHORIZED → RUNNING → STOPPED`;
2. contrato de preferencia por ámbito, congelada por ejecución y reversible;
3. ledger de superficies ricas con lease y revocación;
4. primer adapter real, seleccionado por conformance y no por prestigio del proveedor;
5. test end-to-end acotado sin inferencia ni herramientas antes de permitir prompts o efectos.
